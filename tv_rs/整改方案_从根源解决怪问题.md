# tv_rs「怪问题」根因整改方案

> 目标：不再逐个打补丁，而是把「多窗口生命周期」「主线程阻塞」「调试设施污染生产」三类共性病根，从架构层一次性锁死。  
> 适用范围：`tv_all/tv_rs`（Rust 版，Tauri + mpv + WebView2 官网源）。  
> 版本基线：commit `694f0eb`，tag `v2.10.47`。

---

## 一、已经暴露的三类「怪问题」与共性根因

| 编号 | 症状              | 表面触发                     | 真正病根                                     |
| -- | --------------- | ------------------------ | ---------------------------------------- |
| B1 | 切源后旧直播窗残留、双声道   | 官网源 CCTV-6 → 本机源 TVB 翡翠台 | 多窗口生命周期散落管理，回收靠「同步隐藏 + 后台销毁」的临时补丁，无统一所有权 |
| B2 | 官网源全屏画面缩在中间     | 全屏往返                     | 几何同步是事后缝上的 `sync_live_geometry`，不在会话状态机内 |
| B3 | 每 8 秒卡 6 秒「未响应」 | 主窗 + 直播窗共用 CDP 端口        | 调试设施（CDP 端口）污染生产行为                       |

三者的共同点：**资源（窗口 / 进程 / 调试配置）的「创建—同步—回收」没有一处统一收敛，分散在各模块里堆 `static` + 散落方法。**

---

## 二、根因整改方案（按优先级）

### 方案 1：播放会话管理器（PlaySession / Session Manager）—— 根治 B1、B2

**现状**：官网直播窗、mpv host、嗅`探`窗是三个独立顶层原生窗口，各自靠全局  
`LIVE_WINDOW`（`Mutex<Option<WebviewWindow>>`）、`LIVE_HWND`（`AtomicU64`）和散落的  
`close_live_window` / `raise_live_window` / `sync_live_geometry` 管理。

**改法**：引入单一 `PlaySession`，由它持有一次播放所需的所有句柄，任何模块不得私自关窗。

```rust
/// 一次播放会话的完整资源集合。
/// 一切创建/回收/几何同步都走 SessionManager，模块不得直接碰这些句柄。
struct PlaySession {
    gen: u64,                              // 代次：切换源/切台自增，作回调闸门
    mpv: Option<std::process::Child>,      // 本机源进程（配合 player.rs 的 wait）
    live: Option<tauri::WebviewWindow>,    // 官网源直播窗
    live_hwnd: u64,                        // 直播窗 HWND 缓存
    sniffers: Vec<u64>,                    // 嗅探窗 HWND 列表
}

struct SessionManager {
    cur: Mutex<Option<PlaySession>>,
}
```

- **唯一入口** `SessionManager::replace(new: PlaySession)`：
  1. 取旧会话，`ShowWindow(SW_HIDE)` 同步切断画面 + 音频（微秒级）。
  2. 旧 mpv / 直播窗 `close()` / 嗅探窗回收，**全部丢后台线程** `wait()`/`close()`，不占主线程。
  3. 确认旧会话句柄已全部失效后，才写入新会话。代次 `gen` 自增，所有异步回调里校验 `gen`，不匹配即丢弃（消灭「旧回调冲掉新会话」）。
- **几何同步内建**：`SessionManager::sync_geometry(x, y, w, h)` 一次把所有属于当前会话的窗口统一 `SetWindowPos`，取代现在「前端上报 → `report_stage_rect` → 单独补一次 `sync_live_geometry`」的补丁式调用。
- **`close_live_window` / `raise_live_window` 删除**，调用方一律改为 `SessionManager::drop_live()` / `SessionManager::raise_live()`。

**收益**：切源「关不干净 / 关完还在播」从制度上消失；全屏/退出/切源时的几何同步成为状态机内建步骤，不再漏窗口。

### 方案 2：同步命令白名单约束 —— 根治 B3（主线程阻塞）

**现状**：`#[tauri::command]` 同步函数在主线程执行，任何 `.wait()`/`join()`/`close()` 都会卡窗。

**改法**：

- 封装 `fn blocking<R>(f: impl FnOnce() -> R) -> R`，内部 `debug_assert!` 检测当前是否在主线程；release 下记录到诊断日志。
- 对全部 `#[tauri::command]` 同步函数做一次审计，把 `Child::wait()`、`win.close()`、`recv_timeout` 等阻塞调用全部下沉到后台线程（现有 `player.rs::stop()` 已这么干，作为模板推广）。
- 留一份「同步命令阻塞 API 黑名单」清单入仓库，后续新增命令自觉对照。

**收益**：从机制上杜绝「有人顺手在命令里写了个 `.wait()` 又卡住」。

### 方案 3：调试设施与生产隔离 —— 根治 B3 同源性

**现状**：`debug_port_args()` 现在直接 `String::new()`（靠写死空串才不抢端口）；主窗在 `main.rs:1936` 仍读 `CLEAN_TV_CDP_PORT`。

**改法**：

- 收敛一个 `DebugConfig`，集中管理 CDP 端口、`CLEAN_TV_AUTOPLAY/AUTOFULLSCREEN/SWITCH_AT/SMOKE_PLAY/LOG` 等全部环境变量钩子。
- `DebugConfig::cdp_args()`：`#[cfg(debug_assertions)]` 才返回端口，release 恒空。这样「开着调试就坏生产」不可能再发生。
- 加一条集成测试：release 构建下设定所有 `CLEAN_TV_*` 环境变量，断言运行行为与不设完全一致（或明确只有诊断副作用）。

### 方案 4：固话场景回归脚本 —— 防复发

把现有钩子体系（`CLEAN_TV_AUTOPLAY/AUTOPLAY_SRC/AUTOPLAY_TID/AUTOPLAY_CID/AUTOFULLSCREEN/SWITCH_AT/SMOKE_PLAY`）整理成场景清单，每个场景一条命令：

| 场景     | 目的  | 环境变量组合                                          |
| ------ | --- | ----------------------------------------------- |
| 切源无残留  | B1  | `SWITCH_AT` + `SWITCH_TID/CID/NAME`，本机源→官网源→本机源 |
| 全屏往返铺满 | B2  | `AUTOFULLSCREEN` + `report_stage_rect` 校验       |
| 主线程不卡  | B3  | `spawn_hung_probe` 日志 `[hung]` 全无               |
| 起播自检   | 链路通 | `SMOKE_PLAY="ys:1"`                             |

每次改动跑一遍，任一场景红即阻断合入。

## 三、分阶段落地计划

| 阶段             | 内容                                 | 风险               | 预计改动面                                                                         |
| -------------- | ---------------------------------- | ---------------- | ----------------------------------------------------------------------------- |
| **P0（先做，低风险）** | 方案 3：`DebugConfig` 隔离 + 方案 2 的阻塞审计 | 极低               | `main.rs` 一小块 + 新增审计清单                                                        |
| **P1（根治，核心）**  | 方案 1：`SessionManager` 重构           | 中（涉及换源/切台/全屏主链路） | `official_embed.rs` + `main.rs` + `player.rs`，删除 `LIVE_WINDOW`/`LIVE_HWND` 全局 |
| **P2（防复发）**    | 方案 4：场景回归脚本 + 一条 release 无污染测试     | 低                | 新增 `tests/` 脚本                                                                |

建议顺序：**P0 → P1 → P2**。P0 先落地拿到「调试不再污染生产」的安全底座，再动 P1 的大重构，最后 P2 锁死防复发。

---

## 四、验收标准

1. 本机源 ↔ 官网源反复切台 20 次，任务管理器 + 窗口枚举**无任何残留窗口、无双声**。
2. 全屏 / 退出全屏 / 切源 / 切台，直播窗与 mpv 画面**几何完全一致**（CDP 查 DOM rect + 枚举窗口 rect 双向核验）。
3. `spawn_hung_probe` 连续 60 秒日志**无 `[hung]`**。
4. release 构建设满 `CLEAN_TV_*` 环境变量，行为与不设一致。
5. 场景脚本 4 条全绿。
