# 本机源取流规范（2026-10-26 实测定稿 · v3）

> **一句话结论**：本机源**能播**，但只有 **3/6 分类**在源站 app 路由下有线路。
> 105 个频道（ty/ys/ws）链路完全正常；tv/wintv123/gt 共 173 个频道
> 在**源站层面**就没有播放页（`iptve.php?act=play` 与 `eplay2.php` **双双 404**），
> 不是客户端问题。港澳台的出路是**官网源网页嗅探**，但**必须逐频道实测**：
> 可达站点里既有真出画的（香港衛視，h264 720p），也有被地域封锁的（tvfix.org 返 418）。

## 3. 取真实播放地址的完整步骤（app 版，4 步）

### 步骤 1：拿频道列表（分组）

```
GET https://api1.2026016.xyz/iptve.php?tid=<分组>&app=517
```

| tid | 显示名 | 频道数 | app 路由播放页 |
|---|---|---|---|
| `tv` | 综合 | 75 | ❌ **404** |
| `ty` | 体育 | 21 | ✅ 21/21 可播 |
| `ys` | 央视 | 43 | ✅ 43/43 可播 |
| `ws` | 卫视 | 41 | ✅ 41/41 可播 |
| `wintv123` | 极速港澳台 | 47 | ❌ **404** |
| `gt` | 港澳台 | 51 | ❌ **404** |

解析：`act=play[^'"]*&tid=([a-z0-9]+)&id=(\d+)[^>]*>([^<]+)<`（`core.rs::parse_channels`）。

### 步骤 2：拿播放页（加密线路数据）

```
GET https://api1.2026016.xyz/iptve.php?act=play&tid=<tid>&id=<cid>
```
- 带**完整头** → 含 `<option value="密文">` 的播放页（**13 条线路**，参数 `p=0..12`）
- `tv` / `wintv123` / `gt` → **HTTP 404**（源站 app 路由没有这三个分类的播放页）

### 步骤 3：解密（`core.rs::decrypt_page`）

```
option 值 → 字符反转 → base64 解码 → 与 XOR key 逐字节异或
          → base64 解码 → 替换 token → 去掉密钥前缀
```

app 版 XOR key **不是明文变量**，用**已知明文攻击**反推：

```rust
// core.rs::decrypt_page 第 4 步
let s0 = b64d(opts[0].chars().rev());           // 第 1 条线路的密文
for tmpl in [
    format!("{api}/eplay2.php?token={old}&tid={tid}&id={cid}&p=0&type=.flv"),
    format!("{api}/eplay2.php?token={old}&tid={tid}&id={cid}&p=0"),
] {
    let out0 = b64e(tmpl.as_bytes());
    if s0.len() == out0.len() {                  // 长度匹配即命中
        key = s0 XOR out0;                       // 逐字节异或反推
        break;
    }
}
```

★ `api` 必须是**当前生效的镜像**（抓取与解密**必须同域**）。

★ **Python 复刻的坑**（`tools/_local_decrypt.py` 已踩平）：
Rust 的 raw string `r#""token="\+(\w+)\s*,\s*"token="\+(\w+)""#` 末尾的 `"`
是 **raw string 终止符、不属于模式**；照抄进 Python 会多要求一个字面引号 → 永远匹配不上。
且 `(\w+)` 是**捕获组**，括号不能转义。

### 步骤 4：拿真实流地址

解密出的 URL 形态（**实测 ws 分类 271 条全是这一种**）：

```
https://api1.2026016.xyz/eplay2.php?token=<T>&tid=<tid>&id=<cid>&p=<0..12>&type=.flv
```

它的 **302 跳转链**（跟到底）：

```
eplay2.php?p=0
  └─302→ https://api1.2026016.xyz/v/ysp6.php?token=<T>&xra=4&id=<台标缩写>
          └─302→ http://dbiptv.sn.chinamobile.com/PLTV/88888893/224/3221226984/index.m3u8
```

★ **`/v/*.php` 是 302 的中间跳**（`cqyx`/`ysp6`/`migu8`/`bstv`/`bstv1`/`hunantv`/`bfiptv`，
参数 `token=<T>&id=<台标缩写>[&xra=<档位>]`），**不是**解密产物。
★ mpv **跟随 302 即可播**（实测 `eplay2.php` 直喂 mpv 出画，AV 进度正常）。
★ 台标缩写示例：`gzws`=贵州卫视、`fyzq`=`ys` 分类某台、`sjdl`/`whjp`/`ystq`/`gefwq`/`nxss` 等。

## 4. 678 系 / iptv345（网页版）取流步骤 —— 与 app 版**是两套模板**

### 步骤 1~2：分组与频道

```
GET https://678iptv.com/                → <a href="?tid=tv">綜合</a> / ty / ys / ws / gt
GET https://678iptv.com/?tid=<分组>     → 75/21/43/41/51/17 = 248 频道
GET https://iptv345.com/?tid=gt         → 官网源用的同一后端
```

### 步骤 3：播放页 + 解密（**明文密钥**，比 app 版简单）

```
GET https://678iptv.com/?act=play&tid=<tid>&id=<cid>    → 10 个 <option>
```

```
option → 反转 → base64 → XOR(key + "1df61d08188674a5") → base64 → 换 token → 去 key
```

★ 变量名/函数名/密钥**每次请求都变**（`njzfx`/`uuixt` → `kcbuq`/`brryk`…），
必须**结构化解析**，唯一可靠模式：

```regex
(X)\s*=\s*\1\.split\(""\)\.reverse\(\)\.join\(""\)\s*;\s*\1\s*=\s*\w+\s*\(\s*\1\s*,\s*(KEYVAR)\s*\)
```

✘ 不要用「任意两参调用」去猜密钥变量 —— 会先撞上 base64 解码函数里的
`String.fromCharCode(a1, a2)`，把 `a2`（位运算变量）当密钥。

### 步骤 4：真实流地址 —— **出口已死**

```
https://p.iptv200.com/play.php?token=<T>&tid=<tid>&id=<id>&p=<0..9>&type=.flv
```

「所有直播线路已失效，请稍后重试或手动切换线路！」。

### 6.3 ★ 香港衛視：港澳台第一个真出画（h264 720p）

**链路**（本机源 → 官网源 → 嗅探 → mpv）：

```
本机源 gt:19「香港衛視HKS」（cid=30）
  → 本机源抓线失败（api2.2026016.xyz HTTP 404，源站无该分类线路）
  → 按名回落官网源 → w|香港:18「香港衛視」
  → 官网源直连=false，网页线路=1 条 → 嗅探 http://www.hkstv.tv/live
  → 嗅探命中 https://webcast.hkstv.tv/livestream/mutfysrq/playlist.m3u8 (headers=3)
  → 流可达性预检 200 OK
  → 出画确认 3.0s（mpv 视频窗口已创建）
```

**mpv 日志实证**（`--log-file` 抓的 98906 字节）：

```
[3.126][v][vd] Opening decoder h264
[3.133][v][ad] Opening decoder aac
Video: (h264 1280x720 25 fps)   Audio: (aac 2ch LC 48 kHz)
hls: Opening '.../playlist-2620.ts?hls_ctx=6t9a6050' for reading   ← 分片持续拉取
```

**流结构**：master 清单（109 字节）→ 子清单 `/livestream/mutfysrq/playlist.m3u8?hls_ctx=<8位hex>`
→ TS 分片 `playlist-26NN.ts?hls_ctx=<同一token>`。
★ `hls_ctx` 是**每次会话动态生成**的（实测两次拿到 `750yo415` / `6t9a6050`），
静态页面里没有 → **只能靠嗅探拿**，静态解析必然失败。

**页面形态**：`www.hkstv.tv/live` 是 **Vue SPA**（`index-C4DecsO3.js` 1.2MB），
流地址在**按需加载的 chunk** 里 —— 主 JS 里搜不到 `livestream`/`webcast` 字样，
静态 HTML 与主 JS 都取不到真流 → 这就是**必须用 WebView2 嗅探、静态抓取无效**的实证。

### 6.4 ✗ tiantzhibo.net → tvfix.org：CDN 地域封锁（418）

`www.tiantianzhibo.net` 页面 200（明珠台/東森洋片/東森幼幼/年代新聞），
嗅探出真流 `https://live.tvfix.org/live/pearl/index.m3u8`，但：

| 请求头组合 | 结果 |
|---|---|
| 无 Referer | **HTTP 418**（body 空） |
| Referer + UA | 418 |
| Referer + Origin + 完整浏览器头（Sec-Fetch-*） | 418 |
| `http://` 明文 | 418 |

★ 418 = `I'm a teapot`，是 **nginx geoip / CDN 地域封锁**的标准响应码。
**与 DNS 污染不同**：DNS 正常解析（`live.tvfix.org` → 43.152.157.75 / 43.152.14.157 / 43.152.156.105），
TCP/TLS 也通（能拿到 HTTP 响应），是**应用层按地域拒绝**。
→ 结论：**线路页宿主可达 ≠ 这个频道能播**，真流宿主可能另有一套封锁。

  ```
  https://prd-vcache.edge-global.akamai.tvb.com/__cl/slocalr2526/__c/ott_C_h264/__op/bks/__f/index.m3u8
    ?hdnea=ip=0.0.0.0~st=…~exp=…~acl=…~hmac=…&p=…&_t=…
  ```
- ★ **master 与子清单都只有音频**（`CODECS="mp4a.40.2"`，两个码率 `a128001`/`a128002`），
  `index_admarker.m3u8`（浏览器真正请求的那个）与 `index.m3u8` 是同一份音频 TS
  → **这条链路给不出视频轨**，mpv 只出声音。
- 子清单规则：**只换 path、保留原 hdnea query**（把 query 拼进路径会 403）；
  含 `#EXT-X-KEY:METHOD=AES-128,URI="https://ads.cdn.tvb.com/newskeys/live.key"`。
- TLS：仅 TLSv1.2（TLS1.3 被拒）→ 需 `--tls-verify=no`；
  需 `Referer: https://news.tvb.com/tc/live/83` + `Origin: https://news.tvb.com`。

## 6.5 ★★★ 真流层：源站中转 vs 直连 CDN（2026-10-26 最重要发现）

### 6.5.1 问题的形状

app 版本机源的线路是**两级中转**：

```
eplay2.php?token=..&tid=ty&id=28&p=2&type=.flv
   │  ① 源站首跳（TLS 握手慢，11.8~20.9s）
   ↓  302 Location:
https://t5.iptv200.com:8443/live/deltasport1.flv?sign=..
   │  ② CDN 直连（0.6s）
   ↓
FLV 数据
```

**mpv 默认自己跟这个 302** → 首跳的慢握手把 12s 出画窗口吃光
→ 明明活着的线路被判「未出画面」（实测 gt:50 愛爾達體育1台）。

### 6.5.2 三个时间数字（实测，同一条线路同一时刻）

| 动作 | 耗时 |
|---|---|
| `eplay2.php` 只取 **302 响应头**（不跟随、不读正文） | **0.20 ~ 0.25s** |
| `eplay2.php` **跟随重定向并读流正文**（= mpv 的行为） | **11.8 ~ 20.9s**（6 次里 4 次 TLS 握手超时） |
| CDN 直连（`t5.iptv200.com:8443/live/…?sign=…`） | **0.6s** |

★ 慢的不是源站「处理慢」，是**跟随重定向后要读 FLV 长连接**——
客户端在等正文，而 FLV 是**永不结束的流**，于是读操作被挂住直到超时。
**只看响应头就 0.2s。**

### 6.5.3 源站的 9 条线路分两类（`tid=ty&id=28` 实测）

| p | Location | 形态 | 判活 |
|---|---|---|---|
| 0 | `t129.2026016.xyz/pull-f5-hs.pstatp.com/live/77802b88….flv` | **无 sign**（pstatp 型） | ✘ 死（404，11.7s 才返回） |
| 1 | `t129b…pstatp.com/live/77802b88….flv` | 无 sign | ✘ 死 |
| **2** | `t5.iptv200.com:8443/live/deltasport1.flv?sign=…` | **带 sign** | ✔ **活**（200，0.7s） |
| **3** | `t39.iptv200.com:8443/live/deltasport1.flv?sign=…` | 带 sign | ✔ 活 |
| **4** | `t45b.2026016.xyz:8443/live/deltasport1.flv?sign=…` | 带 sign | ✔ 活 |
| **5** | `t1b.2026016.xyz:8443/live/deltasport1.flv?sign=…` | 带 sign | ✔ 活 |
| 6 | `t129b…pstatp.com/live/93d19615….flv` | 无 sign | ✘ 死 |
| 7 | `t129b…pstatp.com/live/f8124070….flv` | 无 sign | ✘ 死 |
| 8 | （空 Location） | — | ✘ |

★ **死线恰好排在前面**（p=0,1 死 → p=2~5 活 → p=6,7 死）。

### 6.5.4 三条改造（全部已落地并实测）

| 改造 | 位置 | 效果 |
|---|---|---|
| ① **真流层探活**：探速取 302 Location 后，对真流发 `Range: bytes=0-0`（只看状态码，**不拉正文**），404/超时判死 | `main.rs::race_lines` | 死线在 **1.2s** 内被剔除，不再让 mpv 白等 12s |
| ② **真流 URL 交给 mpv**：app 侧先解析 Location，mpv 直连 CDN | `net.rs::resolve_stream_url` + `race_lines` 尾部兜底 | 首跳 20.9s → **0.2s**；出画从「超时」变 **3~10s** |
| ③ **探速覆盖更多线路**：5 条 → **9 条**，真流探活超时 2.5s → **1.2s**，预算 12s → **20s** | `main.rs` 调用点 | 死线不再把预算耗光，活线能被探到 |

### 6.5.5 实测效果（同一批频道）

| 频道 | 改造前 | 改造后 |
|---|---|---|
| gt:50 愛爾達體育1台 | ✘ 12s×3 全灭 | ✔ **出画**（h264 720p + aac） |
| gt:51 愛爾達體育2台 | ✘ | ✔ **出画** |
| gt:46 緯來日本台 | ✘ | ✔ **出画** |
| gt:45 緯來體育台 | ✔ | ✔ |
| gt:19 香港衛視HKS | ✔ | ✔ |

★ 真流层判活的**判据是「状态码」**（2xx/206 活，404/超时死），
不是「读到数据」—— 因为 FLV 长连接读正文必然超时，
只有状态码能区分「连上但流是死的」和「连上且流是活的」。
